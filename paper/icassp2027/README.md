## Data represented

- 354 selected rows: 132 MacBook M4 Max, 138 Mac Studio M4 Max, and 84 RTX
  5080.
- 159 scored decode and 159 scored prefill rows.
- 53 scored host--file configurations representing 22 unique GGUF files.
- MacBook: 19 scored configurations, split 15 train and four test.
- Studio (`mac-studio-m4-max`): all 23 manifest files completed; after three Q8
  probes are excluded, 20 configurations are scored, split 15 train and five
  test.
- RTX: 14 scored configurations, split 12 train and two test.
- Decode B2 train/test MAPE: 10.39%/13.11% MacBook,
  12.40%/14.37% Studio, and 10.12%/36.15% RTX.
- Prefill P2 depth-zero train/test MAPE: 4.13%/18.68% MacBook,
  4.27%/22.23% Studio, and 5.86%/108.18% RTX.
- B2 all-target transfer MAPE: 14.47% MacBook, 15.42% Studio, and 20.80% RTX,
  versus target-fitted all-row values of 10.96%, 12.89%, and 13.84%.
- B2 test-only transfer MAPE: 11.59% MacBook, 16.76% Studio, and 35.97% RTX,
  versus target-fitted 13.11%, 14.37%, and 36.15%.
- Rejected two-term all-target transfer MAPE: 17.88%, 16.93%, and 149.33%;
  these are not B2 values.

The fixed test sets span MXFP4, Q4_K, and Q4_K_M, and RTX contributes only two
test configurations. Keep host-separated results and avoid a pooled headline.
RTX residency and an offload curve are not established: `n_gpu_layers=99` is
only a request, no spill telemetry was collected, and no lower-`ngl` sweep
exists.

Measurement quality is also host-specific. Decode maximum CV is 3.035% on
MacBook, 2.304% on Studio, and 1.652% on RTX. Prefill was not gated; 8/66
MacBook and 29/42 RTX prefill rows exceed 3%, whereas all 69 Studio prefill rows
are below 1%.

## Regenerate analysis and figures

From the repository root on macOS:

```bash
.venv/bin/python -m llmperf.analyze
.venv/bin/python -m llmperf.refine
.venv/bin/python paper/icassp2027/generate_main_figures.py
.venv/bin/python paper/icassp2027/generate_supplement.py
```

On Windows, replace `.venv/bin/python` with
`.venv\Scripts\python.exe`. No model download is needed to regenerate the
archived analysis because publication paths use the frozen metadata snapshot.

## Build with the pinned macOS Tectonic binary

From this directory:

```bash
export TECTONIC_CACHE_DIR=/Users/lun/.local/share/gguf-perf/tectonic-cache
TECTONIC_BIN=/Users/lun/.local/share/gguf-perf/tectonic-0.17.0/tectonic

mkdir -p build supplement-build

"$TECTONIC_BIN" --only-cached --keep-logs --keep-intermediates \
  --outdir build main.tex
cp build/main.pdf gguf-throughput-icassp2027.pdf

../../.venv/bin/python generate_supplement.py
"$TECTONIC_BIN" --only-cached --keep-logs --keep-intermediates \
  --outdir supplement-build supplement.tex
cp supplement-build/supplement.pdf gguf-throughput-supplement.pdf
```

The equivalent Windows runner path recorded by the earlier environment is
`C:\Users\lun\AppData\Local\gguf-perf\tectonic-0.17.0\tectonic.exe`.
